# Change map: every surface a change must touch

SlopStopper is a suite adopters install, so one change usually lands in
several places: the CLI, a workflow, the installer, the config schema, the
docs and the two Claude Code skills. This table is the checklist;
`cli/tests/test_check_registration.py` enforces the rows a test can, and
`ss:hygiene:docs-accuracy` catches drift between the layers.

| Change | Affects |
| ------ | ------- |
| New quality check | Write `cli/slopstopper/checks/<module>.py` (copy `cli/slopstopper/checks/smoke.py` rather than the plumbing, because a Playwright-backed check describes itself with a `_playwright.Check` and its `run()` is one call to `_playwright.run_check`, so smoke, e2e, accessibility and broken-links share the whole flow; a Snyk-backed check builds on `cli/slopstopper/checks/_snyk.py` the same way: `_snyk.run` for the invocation, `_snyk.gate` for the `fail_on` verdict), add workflow under `.github/workflows/ss-*.yml` (start from `.github/actions/ss-setup`; URL-driven → `ss-resolve-url`; SHA-pinned, least-privilege, `timeout-minutes`, tokens and URLs through `env:`), add `task ss:<category>:<action>` target, add to `install.sh`'s `GENERIC_WORKFLOWS`, classify it in [`cli/slopstopper/data/profiles.json`](../../cli/slopstopper/data/profiles.json) (does it apply to an API? a library?) and map it in `profiles.CHECK_WORKFLOWS`, add a label to `badges.py`'s `WORKFLOW_DISPLAY`, add its `name:` to `ss-pr-summary.yml`'s and `ss-workflow-failure-issue.yml`'s `workflow_run.workflows` (no globs, and an omitted name never re-renders the summary), pass `--status` on its `emit --target pr-comment` line, add a `DOC_HEADINGS` row in `cli/tests/test_check_registration.py` plus `cli/tests/checks/test_<module>.py`, document it under `docs/<category>/` and route the doc, add its `cli/slopstopper/checks/<module>.py` path under its category label in `.github/labeler.yml` (the workflow and docs globs there already match by prefix; the registration test fails until the module is listed), mention in `docs/runbooks/INSTALL.md`, add its badge to `README.md`, **add to the skill duo**: workflow inventory + Pass A/B example in [`slopstopper-install`](../../.claude/skills/slopstopper-install/SKILL.md) (`.claude/skills/slopstopper-install/references/install.md`, `.claude/skills/slopstopper-install/references/verify.md`), reproduce row + gotcha row in [`slopstopper-triage`](../../.claude/skills/slopstopper-triage/SKILL.md) (`.claude/skills/slopstopper-triage/references/reproduce.md`, `.claude/skills/slopstopper-triage/references/gotchas.md`). A Snyk-backed check also gets a row in the data-flow table of `docs/security/SNYK.md` |
| Renaming a `task ss:*` target or env var | `Taskfile.ss.yml`, `docs/<category>/README.md`, **both skills**: `slopstopper-install` (`.claude/skills/slopstopper-install/references/verify.md` local-task commands + aggregates, `.claude/skills/slopstopper-install/references/refresh.md` "Re-apply customizations"), `slopstopper-triage` (`.claude/skills/slopstopper-triage/references/reproduce.md`) |
| Editing `install.sh` (esp. `GENERIC_WORKFLOWS` or post-install stdout) | `install.sh` (the `REPO_URL` must always match this repo's actual location, and the `cli:` block it seeds must name the tag it ran from), `slopstopper-install` `.claude/skills/slopstopper-install/references/install.md` ("what it writes" lists + Step 3 inventory) |
| Changing the install/toolchain mechanism (the `cli:` git pin, `SLOPSTOPPER_CLI_SPEC`, `install.sh` prereqs, the mise pins) | The surfaces that describe how to install/upgrade: `cli/README.md`, [`docs/architecture/README.md`](../architecture/README.md) (toolchain section + layout), `docs/runbooks/INSTALL.md`, `docs/runbooks/UPGRADE_CLI.md`, `docs/runbooks/RELEASE.md`, `README.md`, `.github/actions/ss-setup/action.yml`'s header comment, **both skills**. Keep these in lockstep by hand |
| Adding a Snyk product, changing what a Snyk check sends to Snyk, or adding an egress host | `cli/slopstopper/checks/_snyk.py` (environment, analytics, exit-code mapping), the check's module docstring ("What leaves the runner"), [`docs/security/SNYK.md`](../security/SNYK.md) (the data-flow table, the egress allowlist, the required-checks list), `mise.toml` if the CLI version moves, `ATTRIBUTIONS.md` |
| Adding a CLI subcommand (`slopstopper <verb> …`) | `cli/README.md`'s CLI surface block, `cli.py`'s module docstring, and the doc for its area (`docs/architecture/PROFILES.md` for `profile`, `docs/architecture/PR_FEEDBACK.md` for `emit` and `summary`) |
| Editing a skill under `.claude/skills/slopstopper-*/` (map or `references/`) | [`install-skill.sh`](../../install-skill.sh) (installs `SKILL.md` + the `references/` it links, so an unlinked reference never ships; adding or renaming a skill means its `SKILLS` array), [`docs/runbooks/INSTALL_SKILLS.md`](../runbooks/INSTALL_SKILLS.md), `README.md` "Docs" bullet, the other skill's "When to hand off" pointer |
| Adding a new `slopstopper-*` skill | New `.claude/skills/<name>/SKILL.md`, `install-skill.sh` `SKILLS` array, `docs/runbooks/INSTALL_SKILLS.md` (trigger-table + What-lands + Uninstall), `README.md` link, "When to hand off" pointers in each existing skill's closing section |
| Removing or renaming a slopstopper-shipped artefact (skill, workflow, template, check module) so adopter repos shouldn't carry it any more | Update `.github/labeler.yml` (a renamed path leaves a dead glob that actions/labeler never reports; the registration test catches a check module, nothing catches the rest). Add to the relevant obsolete-list so re-runs auto-clean it: skills → `OBSOLETE_SKILLS` in `install-skill.sh`; workflows or `.ss/` files → similar list in `install.sh` plus the existing byte-equality scrub if it moved into the CLI package. Then add a row to `slopstopper-install`'s "Clean up redundant artefacts" (`.claude/skills/slopstopper-install/references/refresh.md`) so the agent sanity-check covers it. The principle is that adopter repos should hold only the expected set + their own customisations, and anything else is noise to be flagged or auto-removed |
| Editing `install-skill.sh` (the one skill installer, which `install.sh` runs against its own checkout) | `docs/runbooks/INSTALL_SKILLS.md`, `README.md` if the install command line changes |
| Editing `.slopstopper.yml` schema (adding/renaming a key, changing a default) | [`.slopstopper.yml.example`](../../.slopstopper.yml.example) (the schema reference), [`templates/slopstopper.yml.starter`](../../templates/slopstopper.yml.starter) (the seed `install.sh` copies, whose keys must stay a subset of the schema; a test checks), [`.slopstopper.yml`](../../.slopstopper.yml) (this repo's own config), both skills reference the schema, the script that consumes the new key, `install.sh` if the new key drives installer behaviour, `.github/actions/ss-setup/action.yml` if it is under `cli:` (the action parses that block with the stdlib) |
| Adding or changing a project-shape profile (the `profile:` key) | [`cli/slopstopper/data/profiles.json`](../../cli/slopstopper/data/profiles.json) is the **single source of truth** for profile → workflow sets. The CLI reads it via `slopstopper.profiles` and `install.sh` imports that same module from the source tree, so never add a second copy of the mapping. Then: `.slopstopper.yml.example` (schema), `templates/slopstopper.yml.starter` (its `profile:` comment), [`docs/architecture/PROFILES.md`](../architecture/PROFILES.md), `install.sh` `--help`, `docs/runbooks/INSTALL.md`, **both skills**. A new workflow must also be classified into every profile that should drop it |
| Adding a config-driven knob to a check (new `config.get("<x>")` call) | The check's module docstring (a Configuration block listing the keys it reads + defaults), `.slopstopper.yml.example` (schema; the starter too only if most repos set it), `slopstopper-install` (post-install "tunable knobs" pointer + Refresh-only "new knobs" section), `slopstopper-triage` (the "real / false-positive / threshold" branch should call out the config override) |
| Changing the AGENTS.md-first rules (what `ss:hygiene:entry-files` / `ss:hygiene:docs-structure` enforce, the route form, the budgets, or the entry-file scaffolds) | [`cli/slopstopper/checks/_routes.py`](../../cli/slopstopper/checks/_routes.py) (one copy of the route form + token estimate, shared by both checks), [`cli/slopstopper/checks/entry_files.py`](../../cli/slopstopper/checks/entry_files.py) and [`cli/slopstopper/checks/docs_structure.py`](../../cli/slopstopper/checks/docs_structure.py) (rules + paste-ready snippets), [`cli/slopstopper/data/templates/entry-files/`](../../cli/slopstopper/data/templates/entry-files/) (the four scaffolds, which must stay aligned with this repo's own `README.md` / `AGENTS.md` / `CLAUDE.md` / `docs/README.md`, the canonical examples; `cli/tests/test_entry_file_templates.py` runs the checks on them), `.slopstopper.yml.example` (the `entry_files` + `docs_structure` knobs), `install.sh` (`seed_template` calls), `slopstopper-install` Step 5 (`.claude/skills/slopstopper-install/references/map-pattern.md`) + Refresh-only knobs list, `slopstopper-triage` entry-files/docs-structure gotcha rows, `docs/hygiene/README.md` |
| Adding a new headers-source adapter | New module under [`cli/slopstopper/headers_adapters/`](../../cli/slopstopper/headers_adapters/), register in `__init__.py`'s `ADAPTERS` dict, add to the `format:` documentation in `.slopstopper.yml.example` and `docs/security/CSP_EXCEPTIONS.md`, mention in `slopstopper-install` Step 1.5 and `slopstopper-triage`'s gotcha table |
| Editing a Playwright spec, `playwright.config.js`, or `lighthouserc{,.prod}.json` | **`cli/slopstopper/data/` is the only home**. Adopter repos no longer carry these files by default; the CLI ships them inside the package and resolves `.ss/<filename>` first only if an adopter has explicitly overridden it. Edit under `cli/slopstopper/data/` and the change ships on the next tag |
| Headers / CSP | The file `headers.source` names (single source of truth) and `docs/security/CSP_EXCEPTIONS.md`, in the same PR, or `ss:hygiene:csp-exceptions` fails on the drift |
| Moving a pin in `mise.toml` (`snyk`, `gitleaks`, `node`, `task`) | `mise.toml` only, through a reviewable PR; `ATTRIBUTIONS.md` if the licence or upstream changed; `CHANGELOG.md` for the next tag, because a scanner bump can change verdicts on the same commit |
| Changing what a command prints: a check's stdout, `doctor`, `profile`, `checks list` or the banner | `cli/tests/test_cli.py` pins the `--json` shapes; the human text is free to move, but the skills quote some of it (`references/gotchas.md` symptom column), so grep both skills for the old wording |

The right-hand column flags the skill duo wherever a change would drift either skill from reality, because they name specific workflows, tasks and env vars and silently rot if those change without them. Each skill's closing section carries the same instruction in the other direction.
